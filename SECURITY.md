## 1. OUR SECURITY COMMITMENT

SoftwareLabs considers security, privacy, and responsible engineering essential principles of software development.

We are committed to developing and maintaining software with a focus on:

- Secure software architecture.
- Privacy-first development.
- Responsible data handling.
- Secure authentication and authorization.
- Vulnerability prevention and remediation.
- Transparent and responsible security practices.

Security is an ongoing engineering responsibility across the SoftwareLabs ecosystem.

## 2. REPORTING A SECURITY VULNERABILITY

If you discover a potential security vulnerability in a SoftwareLabs project, we encourage you to report it responsibly.

**Please do not publicly disclose security vulnerabilities before giving the maintainers an opportunity to investigate.**

### How to report

1. Visit the relevant SoftwareLabs GitHub repository.
2. Navigate to the repository's Security section.
3. If Private Vulnerability Reporting is enabled, use the **Report a vulnerability** option.
4. Provide a clear description of the issue and steps to reproduce it.

If private vulnerability reporting is unavailable, contact the project maintainer through their GitHub profile:

https://github.com/Paras367

Please avoid including passwords, private keys, personal information, or other sensitive data in public issues.

## 3. INFORMATION TO INCLUDE

A useful vulnerability report should include:

- A brief description of the vulnerability.
- The affected project and version.
- Steps to reproduce the issue.
- Potential security impact.
- Relevant screenshots, logs, or proof of concept, where safe.
- Suggested remediation, if known.

Please share only the minimum information necessary to demonstrate the vulnerability.

## 4. RESPONSIBLE DISCLOSURE

SoftwareLabs encourages responsible security research.

Security researchers are requested to:

- Avoid accessing or modifying other users' data.
- Avoid disrupting production services.
- Avoid destructive testing or denial-of-service attacks.
- Avoid exploiting vulnerabilities beyond what is necessary to demonstrate them.
- Respect user privacy and confidentiality.
- Allow maintainers reasonable time to investigate and address reported issues.

## 5. SUPPORTED VERSIONS

Security fixes are prioritized for actively maintained SoftwareLabs projects and their latest supported releases.

| Project Version | Security Support |
|---|---|
| Latest stable release | Prioritized |
| Previous releases | Evaluated individually |
| Unsupported / archived releases | No guaranteed support |

Individual projects may define their own support policies.

## 6. SECURITY RESPONSE PROCESS

Reported vulnerabilities may go through the following process:

1. **Acknowledgement** — The report is received and reviewed.
2. **Assessment** — The vulnerability is investigated and its severity evaluated.
3. **Remediation** — An appropriate fix or mitigation is developed.
4. **Verification** — The fix is tested where applicable.
5. **Disclosure** — Relevant security information may be disclosed responsibly after remediation.

Response and resolution times depend on vulnerability severity, complexity, and available resources.

## 7. SECURITY SCOPE

This policy applies to original software and digital products maintained under the SoftwareLabs brand, subject to their individual ownership and maintenance arrangements.

Third-party services, frameworks, dependencies, and infrastructure remain subject to their respective security policies.

## 8. THIRD-PARTY DEPENDENCIES

SoftwareLabs projects may depend on external libraries, frameworks, APIs, and infrastructure providers.

We encourage the use of maintained dependencies, appropriate security configurations, and regular dependency reviews.

Security issues originating in third-party components may require coordination with their respective maintainers.

## 9. SECURITY RESEARCH DISCLAIMER

This policy is intended to encourage responsible vulnerability reporting.

It does not grant authorization to access systems, accounts, services, or data without permission.

Researchers must comply with applicable laws and the terms governing the systems they test.
